# 유체 물리 정밀도 개선 설계

현재 구현에서 확인된 4개 문제의 원인 분석과 개선 설계. 각 항목은
`원인 (코드 위치) → 설계 → 변경 파일 → 검증` 순서로 기술한다.

전제: 정상상태 솔버(GGA)와 과도 솔버(MOC)의 수치 골격은 정상 동작하며
교체 대상이 아니다. 문제는 **손실 모델의 누락**과 **해를 화면에 매핑하는
방식**에 있다.

---

## 문제 1 — 코너·밸브의 국부 고압이 보이지 않음

### 원인

세 가지가 겹쳐 있다.

**(a) 엘보의 손실이 런(run) 전체에 균등하게 발린다.**
`compile.ts:163-165`에서 엘보 타일은 `elbow90` 피팅으로 수집되어
`resistance.ts:74`에서 링크 하나의 `minorK`로 **합산**된다. 즉 엘보 손실은
개별 위치를 잃고 링크 전체 저항에 녹는다.
그리고 `pressureField.ts:82-84`는 타일 압력을 **인덱스 기준 선형보간**으로
계산한다:

```ts
const frac = (order.indexOf(tileId) + 0.5) / order.length;
const pa = pFrom + (pTo - pFrom) * frac;
```

결과적으로 엘보 타일은 양옆 직관 타일과 완전히 동일한 색으로 그려진다.
손실이 어디서 발생했는지가 원리적으로 표현되지 않는다.

**(b) 밸브는 두 노드의 평균값으로 그려진다.** — `pressureField.ts:66-72`

```ts
const pa = (a + b) / 2;
```

반쯤 잠긴 밸브는 상류 고압 / 하류 저압이 정확히 그 특징인데, 평균을
취하면 둘 다 사라지고 중간값(=중립 색)이 된다. 조이면 조일수록 색이
평범해지는, 의도와 정반대의 거동이다.

**(c) 표시량이 정압(static)이라 "부딪히는 압력"을 담지 못한다.**
사용자가 말한 "코너에서 부딪혀서 세지는 압력"은 정압이 아니라 유동의
운동량이 벽면에서 압력으로 회수되는 **정체압(stagnation) 성분**이다.
정압은 유동 방향으로 단조 감소하는 것이 물리적으로 옳으므로, 정압만
그리는 한 코너는 절대 빨갛게 되지 않는다.

추가로 `pressureField.ts:32`는 총수두 H에서 표고만 빼서 압력으로 바꾼다:

```ts
nodePressure.set(node.id, headToPressure(h - node.position.y, fluid.rho));
```

`h`는 총수두이므로 이 값은 정압이 아니라 **총압**이다. 속도수두
V²/2g가 섞여 있다.

### 설계

**1-1. 타일 단위 저항 배분.** 런 내부 압력강하를 인덱스가 아니라 **각
타일이 실제로 소비하는 저항 비율**로 배분한다. 타일 i의 저항 지분은

```
w_i = f·(L_cell/D) + K_i        (K_straight = 0, K_elbow90 = 30·fT)
```

이고 타일 i 출구 압력은 `p_from - (Σ_{j≤i} w_j / Σ w) · (p_from - p_to)`.
엘보 타일에서 압력이 계단식으로 떨어지므로 엘보 **입구면**이 주변보다
높은 국부 고압으로 읽힌다.

**1-2. 정압 분리.** 표시 압력을 총압이 아닌 정압으로 정정한다.

```
p_static = ρg(H - z) - ½ρV²
```

V는 노드가 아니라 **링크**의 값이므로 타일 단위로 계산한다(타일은 항상
정확히 하나의 링크에 속한다). 조여진 밸브 하류에서 정압이 제대로
낮게 읽히는 효과가 여기서 나온다.

**1-3. 벽면 부하(wall load) 필드 신설.** 코너/분기의 충돌 하중을 표현하는
별도 스칼라장을 정의한다:

```
p_wall = p_static + C_imp · ½ρV²
```

`C_imp`는 유동이 벽에 부딪히는 정도의 계수:

| 타일 | C_imp | 근거 |
|---|---|---|
| straight | 0 | 벽면 충돌 없음 |
| elbow45 | 0.5 | 부분 선회 |
| elbow90 | 1.0 | 외벽 정체점 상한 |
| tee (직진측) | 0.2 | 분기부 교란 |
| tee/cross (분기측) | 1.0 | 유동이 분기벽에 정면 충돌 |

C_imp = 1.0은 **완전 정체(정체압 상한)** 를 뜻한다. 이것은 CFD 결과가
아니라 물리적으로 방어 가능한 **보수적 상한 지표**임을 문서와 범례에
명시한다. 같은 ½ρV² 항이 이미 `networkVulnerability.ts`의 API RP 14E
침식 한계가 방어하려는 대상과 동일하므로 기존 분석과 정합한다.

**1-4. 밸브는 평균 대신 상류면 기준 + 분할 렌더.** 밸브 타일은 상류
절반을 `p_upstream`, 하류 절반을 `p_downstream`으로 두 색으로 칠한다.
조일수록 타일 안에서 빨강→파랑 대비가 강해져 스로틀링이 한눈에 보인다.

**1-5. 표시 모드 토글.** 범례에 `정압 / 벽면부하` 전환을 추가하고
**기본값을 벽면부하**로 둔다. 사용자가 기대한 "코너가 빨간" 그림이
기본 화면이 된다.

### 변경 파일
- `src/render/pressureField.ts` — 저항 가중 배분, 정압 변환, `p_wall` 산출
- `src/domain/catalog/fittings.ts` — `C_IMP` 테이블 추가
- `src/render/sprites.ts` — 밸브 2분할 렌더
- `src/ui/Legend.tsx`, `src/ui/store.ts` — 필드 모드 토글

### 검증
- 직관 5칸 + 중앙 엘보 1개 런에서, 엘보 타일의 `t`가 양 옆 타일보다
  엄격히 크다.
- 개도 1.0 → 0.3으로 조일 때 밸브 상·하류 압력차가 단조 증가한다.
- 모든 타일 `p_wall ≥ p_static`.

## 문제 2 — 펌프 없이 흐르고, 십자에서 관성 분배가 없음

### 원인

**(a) IN 타일이 공짜 수두 20 m를 갖고 태어난다.** — `ops.ts:67`

```ts
return { ...base, kind: 'source', head: cellElevation(grid, cell) + 20 };
```

OUT은 `head: cellElevation(grid, cell)` (`ops.ts:69`)이다. 스크린샷처럼
IN/OUT이 같은 행에 있으면 표고차는 0인데 **인위적인 20 m 낙차**가 항상
남아 있다. 펌프와 무관하게 흐르는 직접 원인이다.

**(b) 정지한 펌프가 저항 0인 뚫린 관이 된다.** — `resistance.ts:127-131`

```ts
const head = pumpHead(d.spec, q, d.speedRatio);   // n≤1e-6 → 0
const slope = pumpHeadSlope(d.spec, q, d.speedRatio); // n≤1e-6 → 0
const g = -head;                                   // = 0
const dgdQ = Math.max(-slope, MIN_SLOPE);          // = 1e-4
```

`speedRatio = 0`이면 `g = 0`, 즉 **수두손실이 정확히 0**. 정지 펌프가
저항 없는 지름길이 된다. 실제 정지 임펠러는 상당한 폐색이며 통상
역류 방지 체크밸브가 붙는다. 이것은 표현 문제가 아니라 **물리 버그**다.

**(c) 티/십자 분기에 손실이 전혀 없다.** — `compile.ts:59-61`

```ts
case 'tee':
case 'cross':
  return [{ id: tile.id, type: 'junction', position, demand: 0 }];
```

분기는 손실 0의 순수 노드다. 그리고 `fittings.ts:15-16`의

```ts
teeRun: 20,
teeBranch: 60,
```

는 **카탈로그에 정의만 되어 있고 어디서도 사용되지 않는다.** 직진과
90° 선회의 저항이 동일하므로, 유체가 직진을 선호할 이유가 수식에
존재하지 않는다. 사용자가 말한 "관성" 이 정확히 이 누락된 3배 차이다.

### 설계

**2-1. 분기 손실을 링크 단부에 부착.** 분기 손실은 노드가 아니라 **경로**의
성질이다(어느 포트로 들어와 어느 포트로 나가는가). `compile.ts`는 런을
추적할 때 시작 포트 `dir`과 끝 포트 `result.run.endDir`을 이미 알고 있으므로,
허브의 축(straight-through 축)과 비교해 판정할 수 있다:

- 진입/이탈 방향이 서로 반대(일직선) → `teeRun` (K = 20·fT)
- 90° 꺾임 → `teeBranch` (K = 60·fT)

각 파이프 링크의 `fittings`에 양 끝 판정 결과를 추가한다. 새 물성치가
아니라 **이미 있는 카탈로그 값을 연결만** 하는 변경이다.

효과: 십자에서 직진 경로가 분기 경로보다 3배 싸므로, 하류 저항이
동일하면 유량이 직진으로 더 많이 간다 — 요청한 관성 거동이 하드코딩이
아니라 손실 모델에서 자연히 나온다.

**2-2. 정지 펌프 = 폐색 + 체크밸브.** `resistance.ts`의 펌프 분기를 수정:

- `speedRatio < 0.01`: `valveK`의 닫힘 처리(`resistance.ts:92`, `1e12`)와
  동일한 관례로 매우 큰 유한 저항을 부여해 사실상 차단.
- `PumpTile`에 `checkValve: boolean`(기본 true)을 추가하고 Q < 0 구간에서
  큰 저항을 적용해 역류를 막는다.

전 4상한(four-quadrant) 펌프 모델은 범위 밖이며, 위 처리로 "펌프가
꺼지면 흐르지 않는다"가 **물리에서 유도**된다.

**2-3. IN 기본 수두를 표고와 일치.** `ops.ts:67`을 `cellElevation(grid, cell)`로
바꾼다. 새 IN 타일은 게이지압 0(대기 개방 탱크)에서 시작하고, 낙차가
없으면 펌프가 돌아야만 흐른다. `head` 필드는 Inspector에서 계속 편집
가능하므로 낙차 시나리오도 그대로 만들 수 있다.

> **주의 — 확인 필요:** 이 변경은 기존 프리셋(`examples/gridPresets.ts`)의
> 거동을 바꾼다. 또한 OUT을 demand 모드로 두면 펌프가 꺼져 있어도
> 유량이 강제 추출된다(부과 유량이므로 물리적으로 옳다). 이 경우
> 경고를 띄울지는 제품 결정이 필요하다.

### 변경 파일
- `src/grid/compile.ts` — 단부 분기 판정, `teeRun`/`teeBranch` 부착
- `src/physics/resistance.ts` — 정지 펌프 폐색, 체크밸브
- `src/grid/types.ts` — `PumpTile.checkValve`
- `src/grid/ops.ts` — IN 기본 수두
- `src/physics/networkTransient.ts` — 과도 솔버에 동일 분기 K 반영(정상상태와
  초기조건이 어긋나지 않도록)

### 검증
- 대칭 십자(직진/분기 하류 저항 동일)에서 직진 유량 > 분기 유량.
- `speedRatio = 0`에서 전 링크 |Q| < 1e-6.
- 체크밸브 활성 시 펌프 링크 Q ≥ 0.
- 기존 `steadySolver.test.ts` / `networkTransient.test.ts` 회귀 통과.

## 문제 3 — 물리 완성도와 위험 구간 식별

### 원인 — 가장 큰 발견

`src/analysis/` 전체가 **구현·테스트되어 있으나 UI/워커 어디에서도
import되지 않는다.** 확인:

```
$ grep -rn "from '.*analysis" --include=*.ts --include=*.tsx src | grep -v .test.
(결과 없음)
```

사장된 기능:
- `report.ts:generateReport` — 종합 판정(PASS / ATTENTION REQUIRED)
- `stress.ts:analyzeHoopStress` — ASME B31.3 후프응력 이용률(지속/우발)
- `networkVulnerability.ts` — API RP 14E 침식속도, 펌프 NPSH 여유,
  밸브 캐비테이션 지수 σ
- `pumpDuty.ts` — BEP 70~120% 운전점 이탈 판정

즉 "위험 구간을 파악한다"에 필요한 계산은 **이미 다 있고, 화면에만
연결되어 있지 않다.** 가장 저렴하고 효과가 큰 작업이다.

### 설계

**3-1. 분석 결과를 워커 응답에 포함.** `simulation.worker.ts`의
`SOLVE_STEADY` 처리에서 `generateReport(net, result, fluid)`를 호출하고
`SolveSteadyResponse`에 `findings`를 실어 보낸다. 솔버는 이미 워커에서
도므로 추가 라운드트립이 없다.

**3-2. 위험을 타일에 귀속.** 각 finding에 `ref`(링크/노드 id)를 유지하면
`compile.ts:resolveIssueTile`이 **이미** 타일로 역매핑해 준다. 기존
`WarningsPanel`의 클릭-포커스 동선을 그대로 재사용한다.

**3-3. 위험 타일 오버레이.** 침식 초과·캐비테이션·후프응력 초과 타일에
경고 링을 덧그린다. 압력 색상과 겹치지 않도록 **테두리 마크**로 표현한다
(`sprites.ts:156`의 음압 캐비테이션 마크가 이미 같은 방식).

**3-4. 정압 기반 캐비테이션 판정.** 1-2의 정압이 들어오면 노드 절대압을
`fluid.pv`(`fluid.ts:20`, 온도 보간 테이블 존재)와 직접 비교해 정상상태
캐비테이션을 판정할 수 있다. 현재는 게이지압 음수만 표시한다.

**3-5. 남은 물리 격차(우선순위 순).**

| # | 격차 | 영향 | 비용 |
|---|---|---|---|
| 1 | 분기 손실 누락 (문제 2c) | 유량 분배가 구조적으로 틀림 | 소 |
| 2 | 정지 펌프 저항 0 (문제 2b) | 명백한 물리 버그 | 소 |
| 3 | 총압/정압 혼동 (문제 1c) | 압력 표시 편향 | 소 |
| 4 | 속도수두 회복 미반영 | 관경 변화 구간 오차 | 중 |
| 5 | 정상상태 캐비테이션 미판정 | 위험 누락 | 소 |

4번(관경 변화 시 급확대/급축소 손실과 속도수두 회복)은 현재 런 내에서
관경이 일정하다는 가정 위에 서 있다. 타일별 관경 혼합을 허용하려면
별도 작업이 필요하므로 **이번 범위에서 제외**하고, 대신 컴파일 시
런 내 관경 불일치를 경고로 띄운다(현재는 `compile.ts:170`에서 첫
타일 사양을 조용히 채택한다).

### 변경 파일
- `src/worker/simulation.worker.ts`, `src/worker/protocol.ts`
- `src/ui/store.ts`, `src/ui/WarningsPanel.tsx`
- `src/render/sprites.ts` — 위험 오버레이
- `src/grid/validate.ts` — 런 내 관경 불일치 경고

### 검증
- 침식 한계 초과 네트워크에서 해당 링크의 타일에 경고 마크가 뜬다.
- `report.test.ts`의 기존 판정과 UI 표시가 일치한다.

## 문제 4 — 밸브 개도에 따른 유동의 시각적 반응

### 원인

**(a) 입자 점유수가 유량이 아니라 관 부피에 비례한다.** `particles.ts`의
핸드오프는 유량 가중 추첨(`weightedPick`)이지만, 링크 위 **체류시간**이
L/V이므로 정상상태 점유수는

```
n_link ∝ (유입률 Q) × (체류시간 L/V) = Q·L/(Q/A) = A·L = 관 부피
```

가 된다. 즉 유량과 **무관**하다. 더 나쁘게는, 밸브를 조여 V가 작아지면
체류시간이 길어져 그 가지에 입자가 **오히려 쌓인다.** 원하는 것과
정확히 반대다.

**(b) 밸브 통과 속도가 관 속도와 같다.** `particles.ts:123`

```ts
const speed = Math.abs(lf.velocity) / geo.physicalLength;
```

`steadySolver.ts:201-204`에서 밸브의 velocity는 `Q / A_pipe` — 즉 **관경
기준 평균 속도**다. 실제 조여진 밸브의 개구부에서는 축류(vena contracta)로
훨씬 빠른 제트가 형성되는데, 그 국부 가속이 표현되지 않는다.

**(c) 입자가 크기·투명도 고정인 원점(dot)이다.** — `fluidLayer.ts:11-12, 31-39`
속도 정보가 위치 변화율에만 담기고 형태에 담기지 않아, 전역적으로
느려지는 변화는 눈에 잘 띄지 않는다.

### 설계

**4-1. 유량 비례 점유수(핵심).** 자유 유동 핸드오프 대신 **링크별 목표
입자 수**를 명시적으로 유지한다:

```
n_target(link) = N_total · |Q_link| / Σ|Q|
```

매 재빌드 시 목표치에 맞춰 초과분은 제거, 부족분은 해당 링크에 생성한다.
거의 닫힌 가지는 입자가 눈에 띄게 **비워진다**. 이것이 요청 4의 핵심
효과다.

**4-2. 밸브 국부 제트.** 밸브 링크의 렌더용 속도를 축류 속도로 대체:

```
V_vc = V_pipe / max(θ_eff, θ_min),  θ_eff = characteristicFraction(char, opening)
```

`characteristicFraction`은 `valves.ts:45`에 이미 있다. 밸브 타입별 고유
특성(볼밸브의 quick-opening vs 글로브의 equal-percentage)이 시각적으로
구분되는 부수 효과가 있다. 화면 이탈을 막기 위해 상한을 둔다(예 8×).

**4-3. 속도 기반 스트리크 렌더.** 점 대신 짧은 꼬리를 그리고 길이와
불투명도를 국부 속도에 연동한다. 느린 구간은 흐릿한 점, 빠른 구간은
선명한 선이 되어 속도장이 형태로 읽힌다.

**4-4. 저유량 페이드아웃.** |Q| → 0에서 입자를 얼리지 않고 알파를
낮춰 사라지게 한다. 완전히 닫은 밸브 뒤가 "정지한 점 무더기"가 아니라
"빈 관"으로 보인다.

- `src/sim/particles.ts` — 목표 점유수 재조정, 렌더용 국부 속도
- `src/render/fluidLayer.ts` — 스트리크, 알파 스케일

### 검증
- 개도 1.0 → 0.2에서 하류 가지의 입자 수가 단조 감소한다.
- 총 입자 수는 개도와 무관하게 일정하다(재배치이지 감소가 아님).
- 밸브 타일 통과 속도 > 인접 관 속도 (조임 시).

## 실행 순서

물리 정확도를 먼저 고치고 그 위에 표현을 올린다. 표현을 먼저 고치면
틀린 해를 예쁘게 그리게 된다.

| 단계 | 내용 | 문제 | 위험도 |
|---|---|---|---|
| 1 | 분기 손실 부착 (`teeRun`/`teeBranch`) | 2c | 중 — 기존 유량 분배가 바뀜 |
| 2 | 정지 펌프 폐색 + 체크밸브 | 2b | 소 |
| 3 | IN 기본 수두 정정 | 2a | 중 — 프리셋 거동 변화 |
| 4 | 정압 분리 + 타일 저항 배분 | 1a,1c | 소 |
| 5 | 벽면 부하 필드 + 밸브 2분할 렌더 | 1b,1d | 소 |
| 6 | `analysis/` UI 연결 | 3 | 소 — 순수 추가 |
| 7 | 입자 점유수/제트/스트리크 | 4 | 소 |

1·3단계는 기존 테스트 기대값을 바꿀 수 있다. 각 단계는 독립 커밋으로
두고 회귀를 단계별로 확인한다.
