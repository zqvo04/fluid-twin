# 2D 유체 시뮬레이션 플랫폼 — 구조 개편 계획

3D 디지털 트윈에서 **격자 기반 2D 배관 퍼즐 시뮬레이터**로 전환한다.
사용자가 화면 위에 파이프·밸브·펌프·IN/OUT을 퍼즐처럼 배치하면, 실제 유체역학
방정식으로 압력과 유량이 풀리고, 압력이 색으로(고압=적, 저압=청) 표시되며,
유체가 실제 유속에 맞춰 흐르는 것이 보인다.

---

## 0. 확정된 설계 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 물리 방식 | **하이브리드** — 1D 네트워크 솔버가 진실, 파티클은 그 유속장의 시각화 | 압력·유량이 정량적으로 정확하면서 화면은 유체답게 보인다 |
| 배치 방식 | **격자 + 가변 길이** — 셀 단위 배치, 직관은 여러 셀로 늘림 | 사진의 퍼즐 감각 + 실제 배관 길이 반영 |
| 렌더링 | **Canvas 2D** (의존성 0) | 타일 레이어 캐시 + 유체 레이어만 매 프레임. 부드러운 그라디언트가 쉽다 |
| 3D 코드 | **완전 제거** | `three`/`@react-three/*` 삭제, 물리·도메인 자산은 전량 재사용 |

### 명시적 가정 (다르면 알려주세요)

1. **화면 = 입면도(elevation view).** 세로축이 실제 고도(z)다. 그래야 중력·정수두·
   탱크·펌프 양정이 물리적으로 의미를 갖는다. (평면도 모드는 `gravityAxis: none`
   옵션으로 후에 추가 가능)
2. **셀 크기 = 1.0 m** (프로젝트 설정으로 변경 가능). 배관 길이 = 셀 수 × 셀 크기.
3. **유체 = 물** (기존 `domain/fluid.ts`의 온도 의존 물성). 단상·비압축(과도 해석
   시에만 탄성 압축 고려).

## 3. 격자 도메인 모델

```ts
type Direction = 'N' | 'E' | 'S' | 'W';
type Rotation = 0 | 90 | 180 | 270;

type TileKind =
  | 'straight' | 'elbow' | 'tee' | 'cross' | 'reducer'    // 배관
  | 'valve' | 'checkValve' | 'controlValve' | 'reliefValve' // 밸브류
  | 'pump'                                                  // 회전기계
  | 'source' | 'sink' | 'tank'                              // 경계
  | 'gauge' | 'flowMeter' | 'orifice' | 'blind';            // 계기·기타

interface Tile {
  id: string;
  kind: TileKind;
  cell: { col: number; row: number };
  rotation: Rotation;
  /** 직관 전용: 진행 방향 셀 수 (가변 길이). 그 외 타일은 1. */
  span: number;
  nps: NominalSize;
  schedule: Schedule;
  params: TileParams;   // kind별 유니온: 밸브 개도, 펌프 speedRatio, 소스 수두 …
}

interface GridModel {
  cols: number; rows: number;
  cellSize: number;        // [m]
  tiles: Tile[];
  temperatureC: number;
}
```

**포트 규약** (`ports.ts`): 각 kind는 회전 0°일 때의 포트 집합을 갖는다.
`straight: [E, W]`, `elbow: [N, E]`, `tee: [W, E, S]`, `cross: [N,E,S,W]`,
`source: [E]`, `sink: [W]`. 회전은 방향을 90°씩 돌리는 순수 함수.

**연결 판정:** 셀 A의 포트 `E`와 오른쪽 이웃 B의 포트 `W`가 동시에 존재하면 연결.
한쪽만 있으면 **미연결 포트** → 진단에 표시되고 컴파일 시 막힌 끝(dead end)으로 처리.

## 4. 컴파일러 — 격자를 네트워크로

`compile(grid) → { network, tileToElement, elementToTile }`

1. **포트 그래프 구성** — 모든 타일의 포트를 스캔해 인접 연결 목록을 만든다.
2. **직관 병합** (`merge.ts`) — 같은 방향으로 이어진 직관 run을 하나의 `PipeLink`로
   합치고 길이 = `셀 수 × cellSize`. 중간에 가짜 분기 노드를 만들지 않으므로
   솔버 행렬이 작아지고 물리적으로도 정확하다.
3. **노드 생성** — 분기 타일(tee/cross), 기기 타일(밸브/펌프/계기), 경계 타일
   (source/sink/tank), 그리고 병합된 run의 양 끝에 `NetworkNode`.
   `position = { x: col*cellSize, y: (rows-1-row)*cellSize, z: 0 }`
   (행 인덱스를 뒤집어 화면 위쪽이 높은 고도가 되게 한다.)
4. **링크 생성**
   - 직관 run → `PipeLink` (엘보는 `fittings: ['elbow90']` 으로 K 손실 반영)
   - valve/controlValve → `ValveLink` (opening)
   - checkValve → `ValveLink` + 역류 시 opening≈0 (준정상 반복에서 방향 판정)
   - pump → `PumpLink` (spec, speedRatio)
   - orifice → `PipeLink` + 고정 K
   - gauge/flowMeter → 링크 없음. 측정 지점 태그만.
5. **경계 조건**
   - `source` = `reservoir` 노드, `fixedHead` (정압) 또는 고정 유량 모드
   - `sink` = `reservoir`(정압 배출) 또는 `junction` + `demand`(고정 수요)
   - `tank` = `reservoir`, 수위에 따른 head (Phase 6에서 수위 동역학 추가)
6. **정리** — 소스에도 싱크에도 도달하지 못하는 고립 성분은 네트워크에서 제외한다.
   (특이 행렬 방지) 제외된 타일은 회색으로 렌더링해 사용자에게 알린다.

**양방향 매핑**을 유지해야 결과(노드 수두/링크 유량)를 다시 타일 위에 그릴 수 있다.

## 5. 물리 파이프라인

### 5.1 준정상 모드 (기본)

편집 또는 컨트롤 조작 → 80ms 디바운스 → 컴파일 → 워커 `SOLVE_STEADY` → 결과 반영.
이전 해를 다음 Newton 반복의 초기값으로 재사용해 밸브 슬라이더 드래그 중에도
수렴이 몇 회 반복 안에 끝나게 한다.

결과: 노드별 총수두 `H [m]`, 링크별 유량 `Q [m³/s]`·유속 `v [m/s]`·손실 `hL [m]`.

### 5.2 과도 모드 (수격)

밸브를 급폐쇄하거나 "수격 분석" 버튼을 누르면 워커가 `networkTransient`(MOC)를
돌려 압력 프레임을 스트리밍한다. MOC의 Δt는 매우 작으므로(셀 1m, a≈1200m/s →
Δt≈1e-4s) 실시간 상시 실행이 아니라 **짧은 구간을 슬로모션 재생**하는 방식이다.
압력파가 격자 위를 실제로 전파하는 것이 보인다.

### 5.3 유동 시각화 (하이브리드의 "유체다움")

파티클은 물리 상태가 아니라 유속장의 렌더링이다. 각 파티클은 링크 위 매개변수
`s∈[0,1]`을 갖고 `ds/dt = v/L` 로 이동한다. 노드에 도달하면 **유출 링크의 유량에
비례한 확률**로 분배되므로 화면상의 파티클 밀도가 질량 보존을 따른다.
유속 0이면 미세하게 부유(브라운 운동)해 정체를 표현한다.

> 이 층은 솔버에 되먹임하지 않는다. 즉 "보이는 것"과 "계산된 것"이 어긋날 수 없다.

## 6. 압력 하이라이트

- **압력 계산:** `P = ρ·g·(H − z)` (게이지). 노드 z는 격자 행에서 나온다.
  단위 토글: bar / kPa / mH₂O.
- **컬러 램프:** 기존 `scene/colormap.ts`의 청→시안→녹→황→적 램프를 three 의존
  없이 순수 함수로 옮긴다. 낮으면 파랑, 높으면 빨강 — 요구사항 그대로.
- **파이프 내부 보간:** 링크 stroke를 `CanvasGradient`로 그려 시작–끝 압력을
  선형 보간한다. 마찰 손실이 길이에 대해 거의 선형이므로 물리적으로도 타당하다.
- **스케일:** 기본은 현재 망의 min/max 자동 정규화, "고정 스케일" 옵션 제공
  (편집 중 색이 출렁이지 않게).
- **경고 오버레이:**
  - 부압(P < 0) → 보라색 + 캐비테이션 경고 배지
  - 허용압 초과 → `analysis/stress.ts`로 판정, 적색 테두리 펄스
- **범례(Legend)** 컴포넌트 + 타일 호버 시 정확한 수치 툴팁.

## 7. 렌더링

- 3개 레이어: **배경 격자**(정적) / **타일**(오프스크린 캔버스 캐시, 편집 시에만
  갱신) / **유체**(매 프레임 — 압력 그라디언트 + 파티클).
- 타일 스프라이트는 `Path2D` 벡터로 그린다. 사진처럼 굵은 라운드 조인트, 부드러운
  외곽선, 은은한 그림자.
- 뷰포트: 휠 줌, 스페이스+드래그 팬, DPR 대응.
- 성능 목표: 40×40 격자 + 파티클 800개에서 60fps.

## 8. UI/UX

- **팔레트**: 카테고리별 타일(배관/밸브/기기/경계/계기). 클릭 배치와 드래그&드롭 둘 다.
- **배치 보조**: 커서 셀 고스트 미리보기, 연결 가능한 포트 하이라이트, `R` 회전,
  직관은 드래그로 길이 늘리기.
- **인스펙터**: 선택 타일의 구경/스케줄/개도/펌프 속도 등 편집. 조작 즉시 재해석.
- **결과 패널**: 총 유량, 최대/최소 압력, 펌프 duty point, 진단 경고 목록.
- **디자인**: 기존 `tokens.css` 확장. 라운드 코너, 소프트 섀도, 파스텔 계열
  배경에 채도 높은 배관 색. 배치/삭제/회전에 스프링 트랜지션.
- **저장/불러오기**: `serialize.ts`를 schema v3으로 확장해 `GridModel`을 직렬화한다.
  (네트워크는 격자에서 파생되므로 저장하지 않는다.)

| **1. 격자 도메인 + 컴파일러** | `grid/*` 전체 + 단위 테스트 | 손으로 짠 격자 픽스처 → 기대 노드/링크 수 일치, 직관 병합 검증, 고립 영역 제외 테스트 통과 |
| **2. 렌더러 + 편집기** | Canvas 레이어, 팔레트, 배치/회전/삭제/길이조절, pan·zoom, 저장/불러오기 | 사진과 유사한 배치를 5분 내 제작 가능 (스크린샷으로 확인) |
| **3. 정상상태 + 압력 색** | 워커 연결, 컬러맵, 범례, 인스펙터, 진단 | **해석해 대조 테스트**: 단일 직관 Darcy–Weisbach, 병렬관 유량 분배, 펌프 양정, 밸브 폐쇄 시 하류 유량 0. 전 노드 질량 보존 잔차 < 1e-9 |
| **4. 유동 애니메이션** | 파티클 적분, 분기 유량 비례 배분, 속도 기반 밀도 | 분기 파티클 통과 비율 = 유량 비율 (±5%), 800 파티클 60fps |
| **5. 과도(수격) 모드** | MOC 스트리밍, 압력파 전파 렌더, 시계열 차트 | 기존 transient 테스트 + Joukowsky 식 `ΔH = a·ΔV/g` 대조 (오차 5% 이내) |
| **6. 폴리시** | 프리셋 시나리오, 튜토리얼, 경고 패널, 반응형, 다크/라이트 | 수동 QA 체크리스트 |

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 격자가 커지면 실시간 재해석 비용 | 워커 + 디바운스 + 이전 해 웜스타트. 200 링크까지는 수 ms 수준 |
| 밸브 완전 폐쇄 시 행렬 특이 | 최소 컨덕턴스 ε 유지 (`resistance.ts` 현행 처리 확인 필요) |
| MOC Δt가 너무 작아 실시간 불가 | 상시 실행하지 않고 트리거 기반 짧은 구간 슬로모션 재생 |
| 파티클과 솔버 결과의 불일치 인상 | 파티클은 유속장에서만 파생 — 독립 상태를 갖지 않게 설계 |
| 체크밸브·릴리프밸브의 비선형성 | 준정상 반복 안에서 상태(개/폐) 판정 후 재수렴. 발산 시 완화계수 적용 |
